# MHS · генератор карточек «Секретный промпт»

Локальный генератор визуальных карточек **1080×1920 PNG** для Instagram Stories / Reels.
Читает JSON со 100 промптами и программно рендерит из него 100 карточек одного стиля.

Рендер — не картиночная нейросеть, а **точная вёрстка HTML/CSS в Chromium через Playwright**.
Поэтому все 100 изображений идентичны по стилю и отличаются только номером,
текстом промпта и автоматически подобранной высотой поля ввода.

---

## Установка

```bash
npm install
npx playwright install chromium
```

`npx playwright install chromium` нужен один раз — он кладёт браузер в `~/Library/Caches/ms-playwright`.
Шрифты и эмодзи берутся из системы, сеть при рендере не используется.

## Запуск

```bash
npm run render
```

Одна команда делает всё: находит JSON → проверяет его → чистит `output/` →
рендерит 100 карточек → собирает превью → собирает contact sheet → печатает статистику.

Только проверить JSON, ничего не рендеря:

```bash
npm run validate
```

## Где что лежит

| Что | Путь |
| --- | --- |
| Исходные промпты | `secret-prompts-100.json` |
| 100 готовых карточек | `output/cards/secret-prompt-001.png` … `-100.png` |
| Крупные превью | `output/previews/` (#01, #02, #03, #10, #25, #50, #75, #99, #100) |
| Сетка всех 100 для быстрой проверки | `output/contact-sheet.png` |

### Про JSON

Файл **ищется по содержимому, а не по имени**: генератор сканирует корень проекта
и подхватывает первый JSON, который является массивом объектов `{ id, title, prompt }`.
Переименовывать его не нужно — можно держать хоть `secret-prompts-100.json`,
хоть `prompts.json`.

Перед рендером JSON проверяется: валидность, ровно 100 объектов, уникальные id,
сквозная нумерация 1…100, непустые `title` и `prompt`, формат номера `#01` / `#100`.
Технические огрехи (номер записан как `#1`, потерялся `title`, задвоился id)
чинятся программно, тексты промптов не трогаются. Содержательные расхождения
выводятся в терминал как замечания.

## Перегенерация после правок

Поправили текст в JSON — просто запустите заново:

```bash
npm run render
```

`output/cards` и `output/previews` очищаются перед каждым прогоном,
так что старых картинок не остаётся. Полный прогон занимает ~6 секунд.

## Как устроена карточка

```
project/
├── secret-prompts-100.json   ← данные
├── package.json
├── src/
│   ├── render.js             ← запуск, валидация, рендер, QA, статистика
│   ├── template.js           ← HTML-каркас + fit-алгоритм, contact sheet
│   ├── styles.css            ← вся визуальная система карточки
│   └── utils.js              ← поиск JSON, шрифты, чтение размеров PNG
└── output/
    ├── cards/                ← 100 PNG
    ├── previews/             ← 9 крупных превью
    └── contact-sheet.png
```

Композиция сверху вниз: заголовок → `THE MHS` → череп → воздух → поле ввода
с текстом промпта, кнопками `×`, `+` и отправки.

### Safe zone

Instagram подрезает края в ленте и накрывает верх и низ своим интерфейсом
в Stories и Reels. Поэтому вся значимая графика держится внутри полей
**212 px сверху, 190 px снизу, 84 px по бокам** — они заданы в `styles.css`
переменными `--pad-top`, `--pad-bottom`, `--pad-side`.

### Адаптивная высота поля

Промпты разной длины (476–669 знаков), поэтому высота тёмного блока не фиксирована.
Алгоритм в `template.js` подбирает **самый крупный кегль, который вообще влезает**,
и уже под него — максимальный размер черепа, при котором вокруг остаётся воздух.
Ширина блока, нижний отступ и вся остальная композиция при этом не меняются.

Текущий разброс: кегль **38–46 px**, высота блока **964–1098 px**.
Тонкая настройка — константа `FIT` в `src/render.js`.

### Шрифты

Всё локальное, без обращения к сети:

- заголовок — **Roboto Variable** с осью `wdth` 76 и весом 900, то есть настоящий узкий гротеск;
- текст и подпись — **Inter Variable**;
- череп — системная **Apple Color Emoji** (☠️).

Если этих файлов в системе нет, `template.js` подставит запасные варианты
(Arial Narrow Bold / DIN Condensed / Helvetica). Список — в константах
`DISPLAY_CANDIDATES` и `TEXT_CANDIDATES`.

## Контроль качества

Прогон падает с ненулевым кодом, если что-то не так. Проверяется:

- ни одна карточка не вышла за пределы 1080×1920;
- череп не касается поля ввода;
- заголовок, `THE MHS`, промпт, череп и кнопки реально присутствуют в DOM;
- каждый PNG существует, непустой и имеет размер ровно 1080×1920;
- все превью в contact sheet загрузились.

# Reels: видео и публикация

## Команды

```bash
npm run render -- --scale=2   # кадры 2160×3840 — источник для видео
npm run hooks                 #найти припев в каждом треке из audio/
npm run reels                 # 100 роликов MP4 + подписи
npm run publish               # статус очереди
npm run publish -- --next     # пробный прогон, ничего не публикует
npm run publish -- --schedule # cron / launchd на 3 раза в день
```

## Как собирается ролик

Кадр рендерится в 2160×3840, в видео идёт медленный наезд на 6 % и вывод
в 1080×1920 — картинка всегда уменьшается, поэтому текст остаётся резким.
Длительность 7–10 секунд задаётся треком, звук уходит в fade к концу.
Рядом с каждым `reel-XXX.mp4` лежит `reel-XXX.txt` — подпись, то есть сам промпт.

## Музыка

Треки кладутся в `audio/`. `npm run hooks` прогоняет каждый файл, считает
энергию по полусекундным окнам и находит **все непересекающиеся дропы**,
от самого плотного к менее плотным. Тайминги пишутся в `audio/tracks.json`:

    { "file": "montagem-rugada.mp3", "label": "MONTAGEM RUGADA",
      "duration": 9, "starts": [24, 35, 78, 67, 15, 52] }

Список можно править руками: убрать отрывок, который на слух не зашёл,
или вписать свою секунду.

Раскладка по карточкам двухуровневая: трек меняется на каждой следующей
карточке, а когда очередь возвращается к тому же треку — берётся его
следующий дроп. Пять треков дают 42 уникальных звуковых варианта на серию,
один отрывок повторяется не больше четырёх раз за все 100 роликов.

**Про права.** Instagram сверяет звуковую дорожку с Rights Manager. Трек без
лицензии, вшитый в файл, ведёт к заглушению звука, ограничению охвата или
снятию ролика. Ответственность за то, что лежит в `audio/`, на владельце аккаунта.

**Про трендовый звук.** Музыка из библиотеки Instagram через API недоступна —
у Content Publishing API нет параметра для аудио. Трендовый трек накладывается
только вручную в приложении. Автопостинг работает с тем звуком, который вшит в файл.

## Публикация

Публикатор ходит в Graph API в три шага: создаёт контейнер с ссылкой на видео,
ждёт, пока Instagram его обработает (20–60 секунд), публикует. Состояние очереди
лежит в `output/publish-state.json`, повторно один и тот же ролик не уйдёт.

Что нужно до первого запуска:

1. Instagram-аккаунт Business или Creator, связанный с Facebook-страницей.
2. Приложение Meta с правами `instagram_business_content_publish`,
   `instagram_business_basic`, `pages_show_list`.
3. Долгоживущий токен — 60 дней, потом обновлять.
4. Публичный HTTPS-хостинг для `output/reels/*.mp4`: Instagram скачивает видео
   сам по ссылке, загрузить байты через API нельзя.

Дальше:

```bash
cp .env.example .env    # заполнить своими значениями
npm run publish         # проверить, что окружение видит все переменные
npm run publish -- --next          # пробный прогон
npm run publish -- --next --confirm # первая реальная публикация
npm run publish -- --schedule       # поставить на расписание
```

Без `--confirm` публикатор ничего не отправляет — печатает, что бы он сделал.
Лимит Instagram — 50 публикаций в сутки, 3 в день проходят спокойно.
100 роликов при 3 в день — 34 дня ленты.

Отложенного постинга в API нет: контейнер публикуется в момент вызова.
Поэтому расписание держится на cron или launchd, и машина должна быть включена.

# Рубрика «GitHub-находка»

Вторая серия: полезные open-source инструменты, поданные через выгоду,
а не через название репозитория. Тот же конвейер, свои данные и шаблон.

## Команды

```bash
npm run radar                 # собрать кандидатов через GitHub API
npm run radar:cards           # 100 карточек 1080×1920
npm run radar:cards -- --scale=2   # кадры 2160×3840 для видео
npm run radar:reels           # 100 роликов MP4 + подписи
npm run radar:publish         # статус очереди находок
```

Отдельная карточка на проверку: `npm run radar:cards -- --only=7`.

## Данные

`github-radar-100.json` — 100 отобранных репозиториев. Каждый проверен
запросом к API: существует, не архивирован, звёзды, форки и контрибьюторы
настоящие. Поля: `headline` (хук в две строки), `description` (2–3 строки
по-русски), `about` (родное описание с GitHub), `repo`, статистика.

Собрать кандидатов заново: `npm run radar` — сканирует темы вроде
`self-hosted`, `llm`, `automation`, `no-code` и отсеивает учебники,
роадмапы и подборки ссылок.

## Композиция карточки

Сверху вниз: рубрика синим → `THE MHS` → череп → хук → описание →
карточка репозитория со статистикой. Всё по центру, чёрный фон,
синий только акцентом.

Просвет под карточкой репозитория фиксированный (`.spacer-b`), а весь
свободный остаток уходит в верхний. Поэтому отступ сверху двигает
текстовый блок, не трогая карточку.

## Публикация

Своя очередь (`output/radar-publish-state.json`), своё расписание
(13:00, 16:00, 19:00 МСК) и свой workflow `publish-radar.yml`.
Хостинг общий с первой рубрикой — имена `radar-XXX.mp4` и `reel-XXX.mp4`
не пересекаются.

Оба workflow пишут состояние в одну ветку, поэтому перед коммитом делают
`git pull --rebase --autostash` — иначе push второго отбивается.
